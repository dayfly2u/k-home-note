## A. 꼭 할 것

### A1. 앱 표시 이름이 아직 "K-Home-Note"
- 현재: `app/src/main/res/values/strings.xml` `app_name = K-Home-Note`. 홈 헤더·설정 버전 줄은 이미 "생활달력".
- 할 일: `app_name`을 "생활달력"으로. `applicationId`/패키지명 `com.khomenote`는 그대로(요청서 6장).

### A2. 홈에서 주기성작업 바로 "완료 기록" 진입이 없음
- 시안: Done.dc.html, 요청서 2.3 "홈 행을 왼쪽으로 밀거나 길게 누르면 이 시트를 바로 연다(주기성작업)".
- 현재: `ui/home/HomeScreen.kt` `rowLongClick()`이 일회성작업에만 long-press를 준다. 주기성 행은 탭 → 상세만 가능, 완료 기록하려면 상세에 들어가야 함.
- 할 일: 주기성 행 길게 누르기(또는 왼쪽 스와이프)로 `ReplacementRecordSheet`(새 기록 모드)를 홈에서 바로 연다. 저장은 `ItemDetailViewModel.recordReplacement`와 같은 경로(사진 복사 포함). 목록 보기와 달력 보기 모두 같은 동작.

### A3. 대상 추가·수정 화면이 시안(3-b)과 다름
- 시안: AssetForm.dc.html, 요청서 2.4-b.
- 현재: `ui/asset/AssetFormScreen.kt`는 카테고리를 가로 스크롤 칩으로 고르고, 저장하면 `pop()`으로 목록에 돌아간다(`MainActivity.kt` `Screen.AssetForm` 분기).
- 할 일:
  1. 카테고리 → 2열 큰 버튼(이모지 + 이름, 높이 52dp, 선택은 청록 2dp 테두리 + `#E3EEED` 바탕 + 오른쪽 체크).
  2. 마지막 칸 "+ 새 카테고리"(점선 테두리, 2칸 차지) → `CategoryEditSheet`를 열고, 저장하면 그 카테고리가 바로 선택되게.
  3. 이름 placeholder를 "예: 다이슨 V15, 신한카드, 우리 가족"으로.
  4. 새로 추가할 때만 아래 안내 카드 "저장하면 이 대상의 상세 화면으로 가서 주기성작업을 바로 추가할 수 있어요"(청록 연한 바탕). 저장 후 `pop()` 대신 새 대상의 `Screen.AssetDetail`로 이동(백스택은 목록 위에 상세). 수정 모드는 지금처럼 `pop()`.
  5. 카테고리가 하나도 없을 때도 "새 카테고리" 버튼으로 바로 만들 수 있게(지금은 "설정에서 먼저 추가" 문구만).

### A4. 모아보기 카드에 ⋯(수정·삭제) 메뉴가 없음
- 시안: Assets.dc.html(첫 카드 메뉴 열린 상태), 요청서 2.4.
- 현재: `ui/asset/AssetListScreen.kt` 카드에 ≡ 손잡이만 있고 수정/삭제는 대상 상세에 들어가야 가능(v0.6.2에서 카드 버튼 제거).
- 할 일: ≡ 왼쪽에 ⋯ 아이콘 버튼(36×44dp). 메뉴 "수정"(→ `Screen.AssetForm(id)`) / "삭제"(주황 글자 → 대상 상세와 같은 확인·차단 다이얼로그 재사용). 삭제 로직은 `AssetDetailScreen`의 것을 ViewModel/공용 함수로 빼서 같이 쓰면 됨.

### A5. 카테고리 추가·수정 시트(7-b) 세부
- 시안: CategorySheet.dc.html, 요청서 2.8.
- 현재: `ui/settings/CategoryEditSheet.kt` 바텀시트는 들어갔지만 이모지는 고른 뒤 "이미 다른 카테고리에서 사용 중" 경고만 뜬다.
- 할 일:
  1. 다른 카테고리가 쓰는 이모지는 그리드에서 처음부터 흐리게(alpha 0.3) + 누를 수 없게. 수정 중인 카테고리 자신의 이모지는 정상 표시. 그러면 경고 문구는 필요 없음.
  2. 그리드 아래 안내 "흐린 아이콘은 다른 카테고리에서 쓰는 중이에요".
  3. 이름 입력칸 왼쪽에 고른 이모지 미리보기 상자(52dp, `#E3EEED`, 모서리 16dp).
  4. `CATEGORY_EMOJI_PALETTE`에 기념일용 🎂 🎁 💍 추가(5열 유지되게 한 줄 5개로 맞춰 🎉 🙏 등 함께, 또는 덜 쓰는 것과 교체). 코드 상수만, DB 변경 없음.

### A6. 화면 문구에 "자산"이 남아 있음
- `ui/asset/AssetListScreen.kt:173` "등록된 자산이 없습니다…" → "등록된 대상이 없습니다…"

- 코드·DB 이름(`assets`, `AssetEntity`)은 그대로.

## B. 시안과 다르게 구현된 것 (어느 쪽으로 갈지 Kyle 확인 후)

### B1. 홈 "+" 시트 순서
- 시안: AddPicker.dc.html — "무엇을 추가할까요?"(주기성/일회성 카드) 먼저 → 대상 라디오 목록 + 항상 보이는 "새 대상 만들기" → "다음".
- 현재: `ui/home/HomeAddSheet.kt` — 대상 먼저 고르고 → 주기성/일회성 선택. "대상 추가"는 대상이 하나도 없을 때만 보이고, 만든 뒤 시트로 돌아오지 않는다.
- 최소 할 일(순서는 지금대로 두더라도): 대상 목록 아래에 "새 대상 만들기"를 항상 두고, 만든 뒤 그 대상이 선택된 상태로 이어지게.

### B2. 대상 상세 오른쪽 위 메뉴
- 시안: AssetDetail.dc.html — ⋯ 하나에 "대상 수정 / 대상 삭제".
- 현재: "대상 수정" 텍스트 버튼 + ⋮(삭제만). 기능은 같음. 시안처럼 ⋯ 하나로 합칠지 선택.

## C. 작은 다듬기 (선택)

- C1. 홈 요약 3칸(지났어요/챙길 때/한 달 안)을 누르면 그 섹션으로 스크롤(요청서 2.2 "선택"). 지금은 눌러도 반응 없음. `listState.animateScrollToItem`으로 `section-<band>` 키 위치로.
- C2. ≡ 드래그 손잡이가 텍스트 "≡"(4곳: 모아보기, 대상 상세, 설정 카테고리 등). 시안은 세 줄 아이콘(20dp, `#8D9A9B`) + 44dp 터치 영역 + `contentDescription = "길게 눌러 순서 바꾸기"`.
- C3. 행 ⋯ 메뉴(`ui/common/RowMoreMenu.kt`)의 "삭제"를 주황 글자(`#A2410F`)로, 앞에 작은 아이콘(연필/휴지통). 시안 Assets.dc.html 메뉴 모양.
- C4. 본문 글꼴이 IBM Plex Sans KR Regular/Bold 두 개만 번들돼 있어 시안의 500/600 굵기가 Bold로 보인다. `ibm_plex_sans_kr_medium`(500)과 `semibold`(600)를 추가해 `FontWeight.Medium/SemiBold`에 매핑하면 시안에 더 가깝다(APK 크기 +약 5.6MB, 원하면 생략).
- C5. 레포 `docs/design/2026-10-18-redesign/redesign-brief.md`가 10-18 초안이다. 공유 폴더의 최신 요청서(2.2-b, 2.4, 2.4-b, 2.5, 2.8 갱신분)와 `mockups/*.dc.html` 13개를 같은 폴더에 넣어 두면 이후 작업의 기준이 맞는다.
