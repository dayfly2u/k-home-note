- 시안 소스: 같은 폴더 `mockups/*.dc.html` (색·간격·글자 크기의 기준값. 그대로 실행되는 파일은 아님)

## 0. 진행 원칙

1. **디자인 교체와 신규 기능을 분리한다.** 1단계는 기존 기능 그대로 보기만 바꾸고, 신규 기능은 그 뒤에 하나씩.
2. **CLAUDE.md의 DB 마이그레이션 규칙을 그대로 따른다.** 실기기에 다시 입력하기 힘든 실데이터가 있다. 이 요청서의 1단계는 DB 변경이 없다. [신규-데이터] 항목만 additive `Migration`이 필요하다.
3. 각 단계가 끝날 때마다 실기기에 업데이트 설치로 확인(재설치 금지), 백업 파일 먼저 만들어 두기.
4. `applicationId = "com.khomenote"`, 패키지명은 그대로 둔다(사용자에게 안 보임, 기존 설치 업데이트 유지).

**D-day 구간 기준은 Kyle의 v0.4.12 그대로, 색만 두 가지로 줄인다**:

| 구간 | 배경 / 글자 | 글자 크기 |
|---|---|---|
| 지남 (D+N) | `#B84A16` / 흰색 | 크게 |
| 오늘 ~ 알림 설정일(reminderLeadDays) 이내 | `#FCE9DD` / `#A2410F` | 크게 |

- **v0.5.8의 "일회성 = 연한노랑 배경"은 "한 번" 태그로 바꾼다** (색 정리 때문. 노랑이 낫다면 되돌리기 쉬움).
- 홈 행 왼쪽 카테고리 이모지 상자는 뺐다(색이 많아 보여서). 이모지는 필터 칩과 모아보기 카드에만.
- 글꼴 두 개는 Google Fonts(OFL)라 `res/font`에 번들 가능.
- 카테고리 이모지는 사용자 데이터라 그대로 둔다(칩, 행 왼쪽 아이콘). 그 외 버튼 아이콘은 이모지 대신 벡터 아이콘(Material Symbols 등). 일회성작업 앞의 🔧도 뺀다.
- Material3 `lightColorScheme`에 위 값을 매핑하고 `KHomeNoteTheme` 하나로 감싼다. 다크 모드는 이번 범위 밖.

- **"자산" → "대상"으로 표시만 바꾸기를 제안.** 기념일(우리 가족), 카드(신한카드)까지 담게 되면서 "자산"이 어색해졌다. 코드·DB(`assets`)는 그대로, 사용자 문구만. Kyle이 "자산"이 낫다면 유지.
- "주기성작업 / 일회성작업"은 v0.5.8 결정대로 유지. 홈 행 태그만 짧게 "한 번".
- "구매이력 추가" → "완료 기록"(같은 기능). 이력 섹션 이름 "교체/구매 이력"은 유지.

## 4. 수익화 연결 (무료 + 프로 일회성 결제)

- 무료: 지금 기능 전부(대상 개수 제한은 넉넉하게, 예: 10개).
- 프로 후보: 홈 화면 위젯(오늘 챙길 것), 사진까지 포함한 백업(지금 백업은 사진 제외), 대상 무제한, 빠른 선택 템플릿 확장. 가격은 미정.
- 결제 구현(Play Billing)은 k-golf에서 먼저 해 보고 같은 방식으로 붙인다.

## 5. 추천 구현 순서

1. 테마(색·글꼴·모서리) + 하단 탭 + 설정 화면(카테고리·백업 이동). DB 변경 없음.
2. 홈: 요약 3칸, 섹션 머리, 행 모양. 대상 상세·모아보기 카드 모양.
3. 주기성작업 상세(링, 통계)와 추가 폼(세그먼트, 미리보기, 빠른 선택).
4. 완료 기록 바텀시트 + 홈에서 바로 완료.
5. 앱 이름 반영(아래 6장), 설정의 알림 시각·마지막 백업.

## 6. 앱 이름: "생활달력" (2026-10-18 Kyle 결정)

- 표시 이름만 바꾼다: `strings.xml` app_name("K-Home-Note" → "생활달력"), 홈 헤더의 작은 앱 이름, 설정 하단 버전 줄, 프로 카드("생활달력 프로"). `applicationId`/패키지명 `com.khomenote`는 그대로.
